# Decisions

## 2026-11-05 · Static, no framework

The demo has to open from a URL with no build step, no install, and no server. Vanilla HTML, CSS and JS keep the repository readable to anyone opening it in a browser, and remove a class of deploy failure.

## 2026-11-05 · The kernel is real code, the numbers are not

The six checks execute on whichever proposal the reader selects. Amounts, nonces and hashes are illustrative and labelled as such. The alternative, a scripted animation, would be a claim rather than a demonstration.

## 2026-11-05 · Seven cases, one of each failure

The cases are not anecdotes; each maps to an attack class from the threat model: over-cap, unknown payee, replayed authorisation, poisoned intent, failed delivery, exhausted budget.

## 2026-11-05 · Session cap below the per-transaction cap

Set so that the budget case fails for the budget reason and not the amount reason. The first draft had the refund free the budget early, which let the last case pass; the ordering of checks and the cap were both fixed.

## 2026-11-05 · Dark by default, light on request

Review rooms are dark. The palette is defined once as tokens so both themes are one block apart.

## 2026-11-05 · GitHub Pages over a platform deploy

No account, no token, no build environment. A public repository plus Pages is the lowest-friction way for a teammate to open the thing on a phone.
